IMPLEMENTED PROOF BOUNDARY
- Five isolated projects: Native, Fixture, CrashOwner, Harness, and Tests.
- Root process is created suspended, assigned to a kill-on-close Job Object, verified as a
  member, and only then resumed.
- STARTUPINFOEX does not override hosted standard handles; the pseudoconsole attribute owns
  the console path and CreateProcessW uses inheritHandles=false.
- Synchronous ConPTY output is serviced by exactly one dedicated long-running blocking reader.
- Eleven deterministic scenarios cover Unicode, ANSI, 1 MiB burst output, quiet child,
  stdin question, resize, normal exit, crash, graceful Ctrl+C, ignored Ctrl+C plus hard stop,
  and nested descendants.
- Acceptance run shape is 100 repetitions per scenario plus one 1/4/8-session group per
  scenario, with CPU, working-set, first-output latency, transfer-byte, handle, process-tree,
  and leak evidence.
- Owner-crash evidence records PID plus process-start ticks and verifies exact identities to
  avoid PID-reuse false positives.
- Acceptance is bound to checked-in scenario-manifest and dispatch-packet SHA-256 identities.
- Quick, filtered, reduced, elevated, altered-source, or skipped-owner-crash runs can produce
  diagnostic evidence only and cannot be reported as G0 acceptance.
