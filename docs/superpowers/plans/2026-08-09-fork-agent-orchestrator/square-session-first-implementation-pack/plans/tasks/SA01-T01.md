# SA01-T01 — Detach daemon and live workflows from desktop-window lifetime

- Phase: SA01 — Windows lifecycle and AO platform hardening
- Gate contribution: A1
- Prerequisite: A0 `PASS`
- Scope: AO platform lifecycle only; no Square session/workflow feature

## 1. Objective

Make the Electron window a client of the local daemon rather than the owner of live agent work. Closing or reloading the window must release renderer/UI resources only. A daemon with live sessions, terminals, pending interactions, or recovery work continues; reopening the app reconnects to the same daemon and sessions without duplication.

## 3. Locked behavior

- Closing the last Square window is not permission to terminate the daemon.
- Renderer reload/navigation/crash is not permission to terminate the daemon or agent sessions.
- Explicit `Stop daemon` is distinct from `Close window`/`Quit UI`.
- Application update may later request a controlled daemon stop, but updater behavior is disabled during this slice.
- The daemon may eventually support idle exit, but it may not exit while it owns live work, a pending interaction, a writer/worktree, an active terminal, or recovery/reconciliation.
- Reopening the desktop must connect to the existing compatible daemon before considering spawn.
- A UI must never re-create an AO session just because its previous view/controller was closed.

## 6. Forbidden changes

- no Square domain/API/migration/UI redesign;
- no route/model behavior changes;
- no worktree cleanup change;
- no terminal runtime change except connection/disconnection ownership;
- no new updater/telemetry behavior;
- no arbitrary keep-alive timer with no ownership model;
- no `taskkill`/process-name kill;
- no hidden daemon duplicate;
- no abandonment of child stdout/stderr causing blocked pipes;
- no optimistic renderer state claiming sessions remain alive without daemon evidence.

## 7. Required lifecycle design

Separate these actions explicitly:

```text
CloseWindow
ReloadRenderer
RendererCrashed
QuitUI
StopDaemonWhenSafe
ForceStopDaemon (owner-authorized, later policy)
UpdateShutdown (later)
```

The Electron main process must:

1. resolve existing compatible daemon endpoint/identity;
2. connect when present;
3. spawn only when no compatible owner exists;
4. treat daemon process ownership as separate from BrowserWindow ownership;
5. close renderer subscriptions/WebSockets on window close;
6. leave daemon and agent processes untouched;
7. reconnect and replay/read current state when a window reopens;
8. surface incompatible/stale daemon state rather than spawning blindly.

If Electron spawned the daemon, detachment must not leave unconsumed stdio pipes. Use an appropriate process/stdio strategy and explicit readiness/error logging.

## 8. Daemon safe-exit contract

Add or use a typed status query exposing at least:

- daemon instance identity/version;
- active AO session count;
- active terminal/controller count;
- pending interaction/recovery count where available;
- whether safe idle exit is currently permitted.

Do not implement full Square ownership counts yet. Until they exist, conservative behavior is to keep the daemon alive unless explicit stop is requested and it reports no active AO work.

## 9. Required tests

### Main-process unit/integration

- closing one of multiple windows leaves daemon untouched;
- closing last window leaves daemon alive;
- renderer reload leaves daemon/session untouched;
- renderer crash leaves daemon/session untouched;
- explicit UI quit leaves daemon alive;
- explicit safe daemon stop calls the daemon operation, not process kill;
- reopen connects to existing endpoint;
- incompatible endpoint is surfaced;
- simultaneous reopen/spawn cannot create duplicates (full ownership proof in T02).

### Windows E2E fixture

Using a disposable project and deterministic long-running fixture:

1. start desktop;
2. create/start one session/process;
3. record daemon/session/process identity;
4. close window normally;
5. prove daemon and exact child identity remain alive;
6. reopen desktop;
7. prove same daemon/session/controller generation is displayed;
8. prove no duplicate session/process/worktree;
9. stop fixture through authorized API;
10. stop daemon safely and prove cleanup.

Also test renderer reload and forced renderer-process termination separately.

## 11. Acceptance criteria

- **SA01-AC-01:** closing/reloading/crashing UI does not stop active work.
- **SA01-AC-02:** reopen binds to the exact existing daemon/session rather than recreating.
- **SA01-AC-03:** UI and daemon stop are separate authorized operations.
- **SA01-AC-04:** detached daemon does not block on inherited/redirected stdio.
- **SA01-AC-05:** incompatibility/stale endpoint is explicit.
- **SA01-AC-06:** no product feature or migration is introduced.

## 12. Mandatory STOP conditions

Stop when:

1. safe detachment requires unreviewed OS service installation/elevation;
2. current daemon has no way to identify live ownership and implementing it would overlap T02 materially;
3. reconnect requires recreating AO sessions rather than reading durable state;
4. Electron close semantics cannot be changed without updater/publisher changes outside scope;
5. the only workaround is to hide/disable window close;
6. a child/process leak appears;
7. exact identity cannot be measured;
8. tests require a valuable repository or credentials;
9. source paths exceed approved scope;
10. current upstream behavior differs enough to require an architecture amendment.
