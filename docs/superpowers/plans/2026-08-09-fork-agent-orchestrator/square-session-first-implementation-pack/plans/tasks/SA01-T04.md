# SA01-T04 — Restart reconciliation and controller generation

- Phase: SA01 — Windows lifecycle and AO platform hardening
- Gate contribution: A1
- Prerequisites: accepted SA01-T02 and SA01-T03
- Scope: AO platform/session/runtime reconciliation; no Square workflow model yet

## 1. Objective

After desktop or daemon interruption, reconstruct truthful AO session/runtime state without duplicating an agent, worktree, controller, or process. Establish generation-fenced controller bindings that the later Square role bindings can rely upon.

The task must explicitly record what can be reattached and what must be classified as lost. It must never silently relaunch external work.

## 2. Preflight map

Inspect and report exact locations for:

- persisted AO session records and runtime/controller facts;
- session lifecycle manager/observer/reaper;
- daemon startup reconciliation;
- terminal runtime identifiers and WebSocket controller state;
- process/session/worktree identifiers;
- current resume/reconnect behavior for terminal and Chat controllers;
- API/read model states shown after restart;
- existing controller generation or fencing fields;
- receipt/completion/PR observation after restart.

Use raw SA01-T01/T02/T03 evidence.

## 3. Required classifications

At startup each non-final execution is classified as one of:

```text
REATTACHED_SAME_RUNTIME
RECONNECTED_STRUCTURED_CONTROLLER
ALIVE_UNATTACHABLE
LOST_PROCESS
STALE_BINDING
AMBIGUOUS_PROCESS_IDENTITY
ORPHAN_QUARANTINED
COMPLETED_WHILE_OFFLINE
REQUIRES_OWNER_DECISION
```

Do not collapse these into `running` or `failed` without evidence.

## 4. Controller generation contract

Every interactive/controller binding has:

- stable AO session ID;
- monotonically increasing controller generation;
- controller/runtime kind;
- process/controller identity;
- created/last-observed timestamps;
- state and terminality;
- ownership/reconciliation reason.

Only the current generation can accept input/control. A stale UI or previous daemon generation is denied. Generation changes are durable before new control is accepted.

Later Square `AOExecutionBinding` will reference this generation; do not create Square tables now.

## 7. Reconciliation algorithm

1. acquire the single-daemon ownership from SA01-T02;
2. open/migrate the AO database once;
3. enumerate non-final AO sessions/controllers/worktrees;
4. gather runtime facts without destructive probing;
5. compare exact process/controller/worktree identity;
6. classify each record;
7. increment/fence generation only when a new controller is actually created;
8. persist classification before exposing it;
9. reconnect supported structured controllers or terminal views;
10. never rerun a task automatically;
11. route ambiguous/orphan state to explicit owner recovery/quarantine;
12. resume PR/CI/review observation idempotently.

Process identity should include more than PID where available. Never kill a PID that may have been reused.

## 8. Restart matrix

Test each applicable point:

- UI close/reopen with daemon alive;
- renderer reload/crash;
- daemon graceful restart while idle;
- daemon crash during session startup;
- daemon crash after process start/before persisted controller fact;
- daemon crash during active output;
- daemon crash while waiting for input;
- daemon crash after external process completion/before status update;
- machine-style abrupt termination simulation where safe;
- stale run/controller record;
- missing process;
- PID reused/ambiguous fixture;
- worktree remains but process lost;
- Chat controller resume supported/unsupported;
- terminal runtime reattachment supported/unsupported.

## 9. Idempotency requirements

Repeated startup reconciliation against unchanged facts must not:

- increment generation again;
- create another process/controller;
- duplicate lifecycle events;
- recreate worktree;
- reapply completion;
- re-notify the same terminal interaction without deduplication;
- hide an earlier ambiguous/lost classification.

## 10. UI/API behavior

- clients display recovered/lost/ambiguous state honestly;
- stale clients receive a generation-conflict error when sending input;
- reconnect obtains a current state snapshot and event sequence;
- completed terminal/history remains available where AO retention supports it;
- no optimistic `RUNNING` merely because a record existed before restart.

## 12. Acceptance criteria

- **SA01-AC-20:** restart never silently relaunches or duplicates a session/process/worktree.
- **SA01-AC-21:** current controller generation is durable and stale input is denied.
- **SA01-AC-22:** alive/lost/unattachable/ambiguous/completed classifications are explicit.
- **SA01-AC-23:** repeated reconciliation is idempotent.
- **SA01-AC-24:** supported reconnect/reattach behavior is proven; unsupported behavior is not claimed.
- **SA01-AC-25:** UI/API show authoritative recovery state.

## 13. Mandatory STOP conditions

Stop when:

1. the only recovery path reruns external work;
2. a stale/ambiguous process would need to be killed automatically;
3. generation fencing cannot be persisted atomically;
4. required migration conflicts with upstream sequence or edits an old file;
5. terminal/Chat reattachment limitations are unknown and cannot be measured;
6. one test produces duplicate sessions/processes/worktrees;
7. source changes require Square product schema prematurely;
8. a controller can accept input after losing current generation;
9. recovery depends on provider transcripts/credentials not safely available;
10. evidence cannot distinguish reconnect from relaunch.
