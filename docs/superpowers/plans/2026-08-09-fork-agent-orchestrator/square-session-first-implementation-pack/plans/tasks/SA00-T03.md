## 1. Objective

Produce the owner-reviewable design that makes Square a clearly separate downstream product while preserving Apache-2.0 obligations and preventing the official Agent Orchestrator installation from colliding with Square development or future releases.

This task identifies every name, application ID, data path, run file, process identity, protocol/URL scheme, telemetry source, updater feed, release endpoint, installer identity, and copyright/NOTICE obligation that later implementation must change. It may add Square-owned ADR/config documentation, but it does not perform the complete rebrand or updater implementation.

## 5. Required decisions for owner review

The ADR must propose exact values or clearly marked owner placeholders for:

- product name and short name;
- executable/CLI command strategy (`square`, AO compatibility alias policy);
- Windows app/package/application ID;
- Electron `productName`, `appId`, protocol and user-data location;
- daemon process identity and run-file name;
- default Square data/config/cache/log/worktree roots;
- environment-variable namespace (`SQUARE_*` rather than reusing `AO_*`);
- local API listener policy and port allocation;
- LAN/mobile listener default (disabled unless separately accepted);
- telemetry default (off) and any future opt-in policy;
- updater default/feed/signing/release repository;
- crash-reporting default;
- official AO import/coexistence policy;
- installer/Start Menu/registry/protocol identity;
- Apache license, NOTICE, attribution, source-offer/link, and modified-file notice policy;
- fork version string and upstream provenance shown in diagnostics/about.

## 7. Network and telemetry inventory

For every outbound or listening behavior, record:

- source file/symbol;
- default state;
- endpoint/bind host/port;
- authentication;
- data categories;
- user control;
- Square disposition: retain, disable, replace, gate, or remove;
- implementation task that will enforce it.

Do not claim “no telemetry” or “local only” based solely on README prose; inspect source/config/build behavior.

## 8. Updater inventory

Record:

- current publisher/repository/channel;
- update metadata files;
- startup/check cadence;
- download/install behavior;
- impact on running daemon/sessions;
- signing assumptions;
- failure/rollback behavior;
- all ways an official AO artifact could replace a Square binary.

The recommended Square default before SA14 — Windows release gate is updater disabled. Do not wire a Square feed in this task.

## 9. License and attribution

Verify the exact upstream license in the pinned checkout. The inventory must list:

- upstream copyright/license text;
- NOTICE obligations when a NOTICE file exists;
- third-party notices already shipped;
- files likely to be materially modified;
- how modified files/releases will be identified;
- product/trademark separation;
- attribution placement in source, About, installer, release archive, and SBOM/notice bundle.

This task is not legal advice; unclear obligations are a STOP/owner/legal-review item.

## 11. Acceptance criteria

- **SA00-T03-AC01:** Every known state/runtime identity surface is assigned a distinct Square value or an explicit owner decision.
- **SA00-T03-AC02:** Square cannot accidentally update from the official AO feed under the proposed design.
- **SA00-T03-AC03:** Telemetry and LAN/mobile behavior are disabled by default in the proposed Square policy.
- **SA00-T03-AC04:** Apache attribution and third-party notice handling are mapped to concrete release artifacts.
- **SA00-T03-AC05:** Official AO and Square can coexist without shared state or process ownership.
- **SA00-T03-AC06:** No product behavior is changed by this design task.

## 12. STOP conditions

Stop when:

- license/NOTICE/trademark obligations are ambiguous;
- an identity surface cannot be isolated without architecture changes;
- an updater or publisher path cannot be disabled safely;
- local listener/port ownership cannot coexist predictably;
- Square would need to read/migrate official AO state by default;
- the task starts becoming the full rebrand implementation.

## 13. Completion receipt

The receipt must include the owner decisions still pending and whether SA00-T04 may import/activate the architecture amendment. It must not claim the isolation design is implemented.
