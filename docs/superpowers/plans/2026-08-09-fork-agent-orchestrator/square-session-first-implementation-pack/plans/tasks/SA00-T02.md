# SA00-T02 — Capture the Unchanged Windows Build, Test, Package, and Runtime Baseline

- Slice: SA00 — Fork adoption and reproducible baseline
- Status: dispatchable after accepted SA00-T01 receipt
- Starting branch: `square/main`
- Expected product-code delta: none

## 1. Objective

Build, test, package, and exercise the exact pinned Agent Orchestrator `v0.12.1` source on the target Windows x64 machine before any Square behavior or rebranding is introduced. Record every pass, failure, warning, environment fact, generated drift, and manual observation as upstream-baseline evidence.

The purpose is classification, not repair. A failing unchanged baseline is not automatically a task failure; hiding, fixing, or normalizing it inside this task is a task failure.

## 2. Prerequisites

- SA00-T01 receipt is independently accepted.
- `HEAD`, `square/main`, `v0.12.1`, and `square-base-v0.12.1` all resolve as recorded.
- Working tree is clean before baseline commands.
- Official AO and Square development instances are stopped unless a test explicitly starts them.
- Git, Go, Node/npm, PowerShell, and Windows architecture are recorded.
- At least one harmless disposable Git repository is available for runtime smoke testing.

## 3. Read authority

Read completely:

- `AGENTS.md` from the pinned AO source;
- AO `README.md`, `docs/README.md`, `docs/architecture.md`, `docs/STATUS.md`, `docs/development.md`, `docs/backend-code-structure.md`;
- root and frontend `package.json` scripts;
- `.github/workflows/**` commands relevant to Windows/build/test/package;
- this task packet;
- `scripts/verify-ao-baseline.ps1`.

## 4. Allowed writes

Only evidence and transient build outputs produced by unchanged upstream commands:

```text
docs/square/evidence/SA00-T02/**
docs/square/receipts/SA00-T02.completion.json
```

Generated source/API/sqlc files may be produced temporarily to detect drift but must not be committed or retained as working-tree edits in this task. Build/package outputs remain untracked and must be listed in evidence.

## 5. Forbidden writes

Do not edit:

```text
backend/**
frontend/**
package*.json
backend/go.mod
backend/go.sum
.github/**
resources/**
existing migrations
existing generated source
Square authority documents
```

Do not upgrade dependencies, change environment requirements, suppress warnings, weaken tests, patch Windows behavior, rebrand, or commit generated drift.

## 6. Required baseline matrix

### 6.1 Environment and Git

Capture:

- Windows version/build and x64 architecture;
- PowerShell edition/version;
- Git, Go, Node, npm, Docker, and optional GitHub CLI versions;
- CPU/memory and available disk space;
- repository commit/tree/tag/branch/remotes/status;
- relevant environment variable names, with secret values redacted;
- whether developer mode, symlinks, long paths, antivirus exclusions, or elevation are active.

### 6.2 Clean dependency/install baseline

Run the exact repository-supported install path. Record network access and lockfile integrity. Do not use `npm update`.

### 6.3 Backend baseline

At minimum:

```text
go build ./...
go test ./...
go test -race ./...
go vet ./...
```

Also run the repository root lint command and any documented generated-code drift checks.

### 6.4 Frontend baseline

At minimum:

```text
npm ci
npm run typecheck
npm run test
npm run build
```

Run E2E only when the documented prerequisites are available. Record skipped prerequisites explicitly.

### 6.5 Generated contract baseline

Run documented sqlc and API generation in a disposable copy or reset afterward. Record whether generation changes committed files. Generated drift is a baseline finding, not permission to commit it.

### 6.6 Windows package baseline

Build the documented Windows x64 desktop package. Record:

- command;
- asset filenames, sizes, and SHA-256;
- signing/notarization state;
- package warnings;
- whether the package starts on the same machine;
- whether an existing installed AO instance interferes.

Do not publish.

### 6.7 Daemon/CLI smoke baseline

Using unchanged source and an isolated data directory when the source supports it:

- start daemon/desktop through documented developer flow;
- prove exactly one daemon instance or record duplication;
- record listener/run-file/data paths;
- call a harmless status/list operation;
- shut down through the documented path;
- record process survivors.

### 6.8 Harmless Windows session smoke

On a disposable repository, run one minimal supported agent/session only when credentials are already available and owner-authorized. Do not read or export credentials. Observe:

- session/worktree creation;
- terminal/Chat output and input;
- cancellation;
- process cleanup;
- data persistence after UI reload;
- dirty worktree behavior.

When no provider route is available, record `UNAVAILABLE` rather than failing the whole baseline.

## 7. Evidence requirements

Create a timestamped directory under:

```text
docs/square/evidence/SA00-T02/<UTC>/
```

Include:

- `environment.json`;
- one log per command;
- `command-matrix.json` with command, cwd, start/end, duration, exit code, required/optional, log hash;
- `git-status-before.txt`, `git-status-after.txt`, and `git-diff-after.patch`;
- generated-drift report;
- package inventory and hashes;
- daemon/process inventory;
- runtime smoke notes;
- skipped checks with reasons;
- `summary.json`;
- `manifest.sha256`.

The summary classifies every finding as:

```text
PASS
PRE_EXISTING_FAILURE
ENVIRONMENT_BLOCKED
NOT_APPLICABLE
NOT_RUN_WITH_REASON
```

Do not classify a Square regression because no Square product change exists yet.

## 8. Validation

- Evidence logs exist for every declared command.
- Working tree returns to its pre-task state except evidence/receipt files.
- No dependency or generated source change is committed.
- Package hashes verify.
- Command matrix and summary are internally consistent.
- Secrets and tokens are absent.
- The receipt states whether adoption can proceed, requires an upstream-compatible repair, or is blocked.

## 9. Acceptance criteria

- **SA00-T02-AC01:** Exact pinned source can be reproduced from a clean checkout on the target machine, or every blocking environmental gap is captured.
- **SA00-T02-AC02:** Required backend/frontend/package results are traceable to immutable logs and hashes.
- **SA00-T02-AC03:** Pre-existing upstream failures remain visible and unmodified.
- **SA00-T02-AC04:** The task leaves product source byte-identical to its starting commit.
- **SA00-T02-AC05:** A runtime smoke result records daemon/data/listener/process behavior without altering architecture.

## 10. Mandatory STOP conditions

Stop and request owner guidance when:

- the repository no longer matches the pinned baseline;
- a command would publish, sign with production credentials, or alter a remote service;
- a test requires exposing secrets;
- a build script attempts destructive filesystem operations outside the checkout/data sandbox;
- an official AO installation would share live state with the development run and isolation is not understood;
- Git working-tree changes cannot be cleanly attributed to command output;
- malware/security tooling reports a result requiring owner review.
