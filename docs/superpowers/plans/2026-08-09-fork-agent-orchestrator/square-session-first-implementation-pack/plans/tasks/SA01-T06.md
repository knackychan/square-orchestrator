# SA01-T06 — Windows foundation gate A1

- Phase: SA01 — Windows lifecycle and AO platform hardening
- Type: independent gate review
- Prerequisites: accepted SA01-T01 through SA01-T05
- Result: `PASS`, `CONDITIONAL_PASS`, or `BLOCKED`

## 1. Objective

Decide whether the reused AO Windows platform is safe enough to support Square's durable session, role-binding, workflow, and UI contracts. Review real Windows evidence for daemon/window lifetime, single ownership, ConPTY/process containment, restart/controller reconciliation, and worktree safety.

A1 does not approve Square domain or product features. It accepts the platform behaviors they will rely upon.

## 2. Required inputs

- A0 gate record;
- SA01-T01..T05 receipts and raw evidence;
- ADR-SA01-001..005;
- source diff from A0 commit;
- current build/test/package results;
- all Windows fixture outputs and process/worktree identities;
- any upstream issue/patch references;
- current known limitations.

## 3. Gate criteria

### Window/daemon lifetime

- UI close/reload/crash does not stop work.
- UI reopen binds to same daemon/session where supported.
- explicit daemon stop is distinct.

### Single ownership

- concurrent clients create one daemon/DB writer.
- endpoint/product/protocol/data identity is verified.
- official AO and Square coexist.
- stale/ambiguous state fails safely.

### Terminal/runtime

- interactive I/O, Unicode/ANSI, burst, quiet, input, resize, exit/cancel pass.
- parent stream isolation passes.
- complete descendant cleanup passes.
- no persistent per-cycle runtime resource growth.
- viewer closure is harmless.

### Recovery/controller

- no silent relaunch/duplication.
- current generation fences stale control.
- alive/lost/unattachable/ambiguous/completed are truthful.
- repeated reconciliation is idempotent.

### Worktrees

- clean owned worktrees are removable.
- dirty/untracked/user/in-use/ambiguous work is retained.
- cleanup warning is visible and separate.
- paths with spaces/Unicode and restart pass.

## 4. Critical non-waivable blockers

A conditional pass cannot waive:

- UI closure stopping live work;
- duplicate daemon/database writers;
- process descendants surviving authorized hard stop;
- silent task relaunch after restart;
- stale controller accepting input;
- dirty/user worktree deletion;
- official AO/Square data collision;
- linear runtime resource leak;
- unknown platform behavior represented as healthy/pass.

## 5. Review method

- recompute every evidence manifest;
- rerun selected high-risk tests from clean state;
- inspect source diff and generated migrations/API changes;
- verify no Square workflow/domain behavior entered platform leaves;
- verify no old migration was edited;
- compare machine-readable summaries to raw logs;
- review all accepted limitations and their downstream effect.

## 7. Decision effect

### PASS

Authorize SA02-T01 and SA06-T01 only according to their prerequisites. Do not authorize persistence or workflow implementation before A2.

### CONDITIONAL_PASS

Only bounded non-critical documentation/diagnostic conditions are allowed. Every downstream packet must include them.

### BLOCKED

No SA02 product contract implementation. Create a narrowly scoped `SA01-FIXxx` task and later superseding A1 review.
